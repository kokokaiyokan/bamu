# BOOTH・BLM・Unityの統合管理（0.1.0）

BOOTH Asset Management Utilityを導入したUnityを開くと、Unity内の受信を自動開始します。ChromeがBOOTHの商品情報を取得してUnityへ渡し、商品ファイルは引き続き公式のBLM用リンク経由でBLM自身が取得します。

## 最初の接続・旧版からの更新

必要なものはWindows、Unity2022.3、Chrome116以降、BLM0.5.0（DBスキーマ20261005）です。

1. Unityの再コンパイルを待ち、`Window > BOOTH Asset Management Utility` を開きます。
2. Manager上部の「設定」→「接続設定…」で別ウィンドウを開き、「Chrome（BOOTH）」の受信状態を確認します。
3. 「初期設定」を展開し、「Chrome拡張のフォルダを開く」で拡張フォルダを確認します。Chromeの `chrome://extensions` から読み込みます。導入済みなら拡張を再読み込みしてください。
4. 「接続キーをコピー」し、Chrome拡張へ登録します。旧版の接続キーは引き継ぐので、設定済みなら再登録は通常不要です。
5. ChromeでBOOTHへログインし、BLMも起動します。Chrome拡張の「今すぐBOOTHを確認」を押すと、Unity側へ約5秒ごとに反映します。

既存の `state.json` をUnity側で読み込み、商品・取得ファイル・選択設定・履歴・未完了ジョブを引き継ぎます。最初の移行時は `state.json.pre-unity.bak` を残します。

## 起動・終了と複数プロジェクト

複数のUnityプロジェクトを開いても、1つだけが受信役になります。同じ接続キーとデータを使い、ほかのプロジェクトも統合一覧を参照できます。受信役が終了した場合は、開いている別のUnityが受信を引き継ぎます。再コンパイル時も受信を止め、再開時に処理記録から復旧します。

すべてのUnityを閉じている間はChromeからの同期・新しいBLMへの引き渡し・保存完了の確認を休止します。すでにBLMへ渡したダウンロードはBLM側で続く場合があります。Unityを再度開くと保存確認を再開し、同じ取得リンクを自動再送しません。

Unityを閉じている場合、Chrome拡張は「Unityを開き、コンパイル完了後に再確認してください」と案内します。

## 未登録商品の一括取得

左一覧は商品IDごとに1カードです。配布ファイルやアバター違いでカードは増えません。必要なら商品詳細の取得設定で対象・配布ファイルを調整します。設定保存だけでは取得しません。

「設定」→「BOOTH」→「BLM未登録を一括ダウンロード」を選ぶと、その時点で未登録のVRChat対象商品を取得待ちに追加します。登録済み商品は新版やファイル不足があっても対象外です。分類不明の商品は手動で「対象にする」を指定できます。ボタン押下時点のファイルを確定し、新版の自動取得・選択の自動追従は行いません。

商品詳細の「BOOTHの取得対象・ファイル設定」内にある「一覧・今後の取得対象から除外する」で、VRChat以外の商品などを商品単位で除外できます。除外は全プロジェクト共通で保存され、一覧の再確認や新しい配布ファイルの追加後も維持します。BLM保存物とAssetリンクは保持し、まだBLMへ渡していない取得待ちは取り消します。引き渡し済みの取得は保存確認を続けます。「設定」→「BOOTH」→「除外した商品も表示」を有効にし、商品詳細の「一覧・取得対象に戻す」で解除できます。解除だけではダウンロードしません。

取得待ちは1ファイルずつBLMへ渡します。複数ファイルの商品が途中でBLMへ登録されても、同じ一括指示の残りは継続します。引き渡し前にすでに保存されたファイルを検出した場合は再取得を省略します。

保存物の変化と60秒間の安定を確認し、unitypackage・ZIPの内容検証、ハッシュ、保管、履歴記録を行います。ZIPはCRCも照合します。部分保存や不正な内容を成功扱いしません。30分確認できなければ「取得の確認が必要」で停止し、商品詳細から明示的に再試行・スキップできます。

ファイルの内容確認はバックグラウンドで実行し、UnityのAssets・BLM DB・BLMの商品フォルダへは直接書き込みません。

## タグ・画像・Unityへの導入

商品画像はローカルキャッシュを再利用します。BOOTHの商品タグは編集可能な辞書で絞り、「自動採用／候補表示のみ／辞書参照なし」から選べます。初期値は候補表示のみです。サブカテゴリは辞書外でもクリックで追加できます。タグ見出し横の辞書設定メニューから変更します。

取得したパッケージは同じ商品カードの保存ファイルに表示します。Managerから手動でインポートすると、従来のフォルダ単位の自動リンクと導入履歴へ接続します。

## 保存先と受信範囲

標準は `%LOCALAPPDATA%/bamu`。旧版で設定した保存先も引き継ぎます。

- `connection.json`：Chromeとの接続キー。
- `state.json`：商品情報・対象設定・取得待ち・履歴。更新時に `.bak` を作成します。
- `product-tags.json`、`tag-dictionary.json`：全プロジェクト共通のタグと辞書。
- `thumbnails`：商品画像キャッシュ。
- `blm-objects/<商品ID>/<SHA-256>`：保存内容の保管。
- `blm-receipts/<商品ID>/<ジョブID>.json`：確認記録。

受信は `127.0.0.1:48763` のみ。管理者権限・URL予約は不要です。接続キー・Host・Originを検証し、Chrome拡張のCORSに対応します。リクエストは4MiB、ヘッダーは16KiBに制限します。BOOTHのログイン情報・CookieはChrome内に置き、Unityへ送りません。

BLM保存名や配布名の版表記に依存します。未知形式はハッシュと安定確認を行い、内容検証のあるZIP・unitypackageと同じ保証ではありません。実Editorのライフサイクルと実Chromeの拡張再読み込み後の運用は、検証記録の実施範囲を参照してください。
